# WeKnora P5 反馈、运行与故障保障实施记录

记录日期：2026-09-27  
阶段状态：**反馈、评测发布闸门、缓存、运行观测与负载测量的插件内核已开发；P5 未通过正式服务和业务环境验收**。正式 `knowledge` 插件配置仍保持关闭。

## 1. 阶段目标与完成口径

依据[开发文档 P5](weknora-development-plan.md#p5反馈运行与故障保障)及[技术文档第 11、16～18 节](weknora-technical-design.md#16-缓存设计)，本阶段目标是：

1. 让员工反馈绑定已交付问答的追踪与来源；由业务审核人核实后纳入有版本的评测集，记录反馈去向。
2. 用固定评测集和候选发布清单运行回归，保存配置/代码指纹、逐题结果、费用与时延；未通过或未经独立复核时阻止批准和发布。
3. 对检索缓存按租户、用户、发布、ACL 和配置隔离，命中后重验来源；答案缓存只允许已审核 FAQ，按生效时间提前失效。
4. 提供有权限的审计查询、有限字段的指标与告警判断，以及 429/5xx/超时、重投和索引故障的明确失败处理。
5. 提供区分冷启动、稳定 10 并发和混合入库的压测工具；真实服务、备份恢复和容量/费用结论必须在可授权环境中另行实测。

## 2. 已开发内容

| 项目 | 实施内容 | 主要文件 |
| --- | --- | --- |
| 反馈闭环 | 只有具 `record_delivery` 权限的交付服务可写问答收据；收据保存问题哈希、追踪、状态、来源编号和检索版本，不保存完整答案。员工仅可对本人收据提交幂等反馈，审核人不能自审；问题哈希复核后转入不可变评测样本并递增数据集版本 | [feedback.ts](../src/knowledge/feedback.ts)、[dsh-integration.ts](../src/knowledge/dsh-integration.ts) |
| 评测与发布闸门 | 对提案清单运行注入式影子评测，逐题检查预期状态、必需/禁用来源；失败即不通过。运行与批准由不同人员执行，批准人与提案人分离。数据库触发器要求当前评测集版本的已批准通过记录，既检查 P4 提案审批，也检查最终发布 | [evaluation.ts](../src/knowledge/evaluation.ts)、[0004 迁移](../plugins/knowledge/migrations/0004_p5_feedback_operations.up.sql) |
| 检索/FAQ 缓存 | 查询键包含租户、用户、知识库、问题、配置指纹、发布 ID/epoch、ACL 修订；命中逐条再授权，核对版本和有效期。空结果仅短时缓存；降级/冲突不缓存。FAQ 经独立审核且派生来源仍可读时才允许答案缓存；撤销后拒读 | [cache.ts](../src/knowledge/cache.ts) |
| 观测与审计 | Worker 以结构化字段记录阶段、结果、时延、token、费用微单位、HTTP 状态；审计读取要求 `audit_read`。计算 P95、错误率、429 次数、成本、Outbox 积压，依据配置阈值返回告警代码 | [operations.ts](../src/knowledge/operations.ts) |
| 故障与重投 | 429/5xx/超时归为可重试，401/403/其他 4xx 转人工处置延迟；Outbox 仅在处理成功后确认，租约过期可重领。索引异常沿 P3 问答路径返回 `degraded`，不伪装成空资料或成功 | [outbox-worker.ts](../src/knowledge/outbox-worker.ts)、[query.ts](../src/knowledge/query.ts) |
| 负载工具与页面 | 可注入真实问答/入库回调，分别报告冷启动、稳定负载和入库混合场景的请求数、失败率、P50/P95 与费用；中文只读反馈评测台按可信租户读取，提供[合成静态预览](../examples/knowledge-p5-feedback-preview.html) | [load-test.ts](../src/knowledge/load-test.ts)、[feedback-workbench.ts](../src/knowledge/feedback-workbench.ts) |

P5 数据保存在插件自有 `hz_p5_*` 表，不修改 WeKnora 上游表。**迁移 0004 生效后，已有 P4 `approved` 提案若没有当前数据集版本的合格评测记录，会在发布时被挡住；新提案连审批也会被挡住。**上线前须建立受控评测集、影子评测适配器和审核责任人，再演练迁移。`0004...down.sql` 会删除 P5 反馈/评测/指标数据；只可在备份、保留期与回退影响确认后使用。

## 3. 验证记录

- Windows `npm.cmd run build`：TypeScript 编译通过。
- `node --test dist/test/knowledge-p5-*.test.js`：P5 **15/15** 定向测试通过。覆盖反馈追踪防伪、人员隔离、评测集版本失效、双人复核、发布硬闸门、缓存撤权与生效边界、FAQ 审核、指标权限、429/401 重投、旧租约恢复、索引降级、10 并发合成测量与页面转义。
- WSL Ubuntu `npm test`：项目全量 **107/107 通过**，约 127 秒。P5 新增并行 PGlite 用例后，原默认并行运行在当前 WSL 上推进到第 28 项即长时间停滞；已停止该次任务，并将项目测试脚本固定为 `--test-concurrency=1`，随后用同一套全量用例复跑通过。此记录不等于正式 PostgreSQL 性能结论。
- 数据库测试为 PGlite + 合成资料；没有连接正式 PostgreSQL、WeKnora、真实模型/索引、企业身份或业务资料。

## 4. 尚未完成的 P5 正式验收

| 闸门 | 当前缺口 |
| --- | --- |
| 反馈与评测 API/页面 | 领域服务、只读 HTML 和 DSH 可选收据钩子已存在；尚未挂到主程序受保护路由。真实 `record_delivery` 凭据分离、知识库级审核职责、问答追踪的持久调用路径仍需联调。 |
| 真实影子评测 | `EvaluationRunner` 是注入接口；还没有可在候选发布清单上检索/生成而不改变活动快照的 WeKnora 适配器，也没有获业务确认的制度/合同标注集。当前合成通过不代表语义正确率。 |
| 配置与门槛冻结 | 评测运行保存配置/代码指纹，但候选提案尚未绑定部署配置；需在 P0/P6 冻结并核对实际执行配置，否则不能以某次合成运行证明当前模型配置安全。 |
| 缓存和观测部署 | 内存缓存仅供开发验证；Redis 适配器、Outbox 消费部署、OpenTelemetry/Prometheus/Alertmanager 接线、保留期和告警阈值仍缺。指标记录接口尚需挂入真实 OCR、检索和模型调用。 |
| 故障与恢复 | 429/5xx/超时、租约与索引异常已在合成环境验证；尚未做真实供应商限流、进程强杀、索引损坏、备份/恢复及来源抽样复核。请按[故障处置与恢复清单](weknora-p5-runbook.md)执行。 |
| 容量/费用 | 10 并发工具已验证调度与统计，未调用真实 DSH、WeKnora、OCR/Embedding/重排/生成 API，不能宣称 P95≤20 秒、容量达标或费用范围；需固定资料/模型/输出长度后分别测冷启动、持续请求和并行入库。 |

本阶段不导入真实资料、不启用真实模型付费调用、不修改服务器、生产权限或备份。P5 后按已确认阶段计划还剩 **P6 试点、调优与正式验收 1 个阶段**；P0～P5 仍各有正式集成验收缺口，不能仅凭阶段编号视作已上线。
