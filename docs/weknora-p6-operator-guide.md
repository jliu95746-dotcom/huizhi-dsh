# 知识库试点操作与维护手册（待真实系统联调）

本手册用于 P6 培训准备，尚未完成培训，也不代表正式页面已经上线。当前可查看的只有[合成只读验收预览](../examples/knowledge-p6-acceptance-preview.html)。正式员工和管理员入口、按钮名称及权限须在主程序接入后再核对。

## 员工如何使用

1. 从慧智中枢已登录会话提问，明确制度适用部门、日期、合同主体或编号；范围不清时按系统提示补充。
2. 查看答案引用的资料名称、版本、页码或表格单元格和有效时间；重要业务决定以权威原件及负责部门复核为准。
3. 若返回“资料不足”“冲突未裁决”或“需要澄清”，补充范围或联系资料负责人，不将这些状态解读为肯定结论。
4. 发现过期、解析错误、漏资料、引用错误或答案问题时提交反馈，记录问题发生的 trace ID 和错误类别；不得在自由文本中粘贴无权限资料或密钥。

## 资料负责人如何维护

1. 登记来源系统、权威部门、适用范围、版本关系、生效与失效时间、访问范围和保密级别。缺少这些信息的资料留在待确认状态。
2. 查看解析、清洗、切分及关键字段差异；对金额、日期、编号、否定词、条款、表头与单位逐项复核。
3. 对重复和矛盾候选给出可追溯裁决；替代关系或部门例外必须指出胜出规则和适用范围。
4. 新版本先完成处理与评测，再由独立审核人批准；紧急撤销、普通更新和历史查询分别记录影响。
5. 把真实失败案例经业务确认后送入隔离评测集，按资料类型和问题类型重跑。不要把用户反馈或模型生成摘要直接当成权威规则。

## 运维和值守如何检查

1. 每日检查 Worker 积压、失败页、模型 429/5xx、问答降级、费用、索引完整性、引用打不开和过期派生内容。阈值、值守人和升级路径须在试点前冻结。
2. 发布前核对固定候选配置与 P5 已批准评测，检查 G-01～G-09、质量、10 并发、迁移、备份恢复、回退、告警、培训及责任证据均来自真实环境。
3. 备份与恢复按[P5 演练清单](weknora-p5-runbook.md)执行，记录实际 RPO/RTO、来源抽样、索引重建和成本；故障时先保留 trace ID、事件 ID 与迁移/配置版本。
4. 发布后核对授权允许与拒绝路径、当前与旧文档版本、缓存撤权、引用定位、队列和告警；异常时按事先冻结的应用、索引、业务文档回退方案分别处理。

正式培训记录应包含部门、日期、培训材料版本、参加范围、问答与反馈操作练习、资料维护责任人、值守安排及复核人。人员名单和内部资料保存在受控系统，不写入 Git。
