# WeKnora P6 试点、调优与正式验收实施记录

记录日期：2026-09-27  
阶段状态：**候选配置冻结和验收证据闸门内核已开发；真实试点与正式验收未通过，也未生产发布**。

## 本阶段开发目标

依据[开发文档 P6](weknora-development-plan.md#p6试点调优与正式验收)与[技术文档第 18、20、21 节](weknora-technical-design.md#18-反馈与业务评测)，本轮先让正式候选版本具备可检查、可追溯的验收入口：

1. 候选版本绑定已审批发布提案、当前评测集、经独立批准的评测运行、插件代码版本和解析/清洗/切分/检索/Prompt 及模型配置指纹。
2. 试点失败案例、分类质量、持续 10 并发、配置核验、迁移/备份/回退/告警演练、培训和责任分配，与 G-01～G-09 分别留证。
3. 证据必须由可信存储验证器核对摘要及候选版本关联；业务与技术负责人分人签认。证据变得不可读、评测集更新或提案变更时，候选状态重新阻断。
4. 保留真实试点、模型供应商、主程序入口和生产部署的边界；合成测试只能证明闸门逻辑。

## 验证与实际边界

- Windows `npm.cmd run build` 编译通过；`node --test --test-concurrency=1 dist/test/knowledge-p6-acceptance.test.js`：**3/3 通过**。PGlite 和合成资料覆盖配置不符拒绝冻结、跨租户不可读、可信证据验证、通用审核人不能代签、签认后锁定、证据/评测集失效重新阻断，以及 0005 迁移回退保留 P1～P5 表。
- WSL Ubuntu x86_64 执行 `npm test`：项目全量 **110/110 通过**，约 141 秒。该结果仅是源码与合成数据回归，不是正式 WeKnora、模型或业务试点验收。
- `ready` 仅表示该候选在**当前验证器返回的证据状态**下具备所列签认；证据验证器必须由部署方连接受控存储，核对摘要、内容类型、环境、候选配置和签发来源，不能用“文件存在”或客户端自报代替。
- 冻结配置的哈希由插件计算，但配置内容仍来自调用方；`config_verified` 必须由可信部署适配器对实际镜像、插件包、迁移和运行配置逐一核对，不能只接受提交时填写的值。
- 当前测试验证器是合成桩，不含企业身份、实际资料、真实 WeKnora 影子检索、模型 API、Docker/Ubuntu 服务、主程序受保护 API、告警系统或备份恢复结果。
- 本机复核仅有 `fixtures/knowledge/服务流程.txt` 演示文本；Docker Engine 返回 `failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine`。因此本轮没有启动固定 WeKnora 服务，也没有真实试点压测或恢复演练。
- 当前权限对象只表达租户级能力，尚未接入企业身份系统的知识库级审核职责。正式管理 API 必须补上知识库范围校验后才能开放候选、证据与签认操作。
- 本轮未部署生产、未外发业务资料、未批量调用付费模型，也未认定建议的质量或 P95 指标达标。

## 正式 P6 仍需执行

按[试点与验收记录模板](weknora-p6-pilot-acceptance.md)收集证据，先补齐 P0～P5 集成缺口，再选定试点部门和资料负责人。真实失败案例只能在有权限的受控环境流转；修复必须进入隔离评测和按类型回归。业务与技术负责人冻结模型、配置、版本、RPO/RTO、预算和阈值，完成员工培训及值守分工。在隔离环境实际演练迁移、备份恢复、回退与告警，记录恢复耗时和失败项。取得业务和技术签认及既定生产授权后，再由正式部署系统执行发布并保存发布记录。

当前项目仍没有上述真实证据，P6 **未通过正式验收**。现有静态页面不是主程序管理页面；正式入口仍需接入可信身份与插件服务端授权。
