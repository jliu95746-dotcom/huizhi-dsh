## 1. 目标与已确认范围

以完整 DSH `knowledge` 插件交付企业知识库，WeKnora 作为插件内部知识引擎。插件负责资料接入、解析治理、权限与版本、检索、证据、反馈、管理页面及运维入口；DSH 通过 MCP 调用已授权的知识工具并生成最终回答。MCP 是让模型通过标准接口调用业务工具的协议。

| 项目 | 已确认内容 |
| --- | --- |
| 使用方式 | 企业内部知识中枢，支持部门和用户权限隔离 |
| 交付形态 | 一个 DSH `knowledge` 业务插件；插件可由多个进程和容器组成，但对主程序保持一个能力边界 |
| 用户规模 | 100 名员工，目标支持 10 人同时提问 |
| 首期资料 | 制度、合同、PDF、Word、扫描件、图片中的文字与表格、Excel/CSV 表格 |
| 模型方式 | OCR、Embedding、重排、抽取和生成能力调用模型 API；供应商由用户后期选择，当前实现保持适配接口 |
| 脱敏选择 | 用户明确选择无需脱敏时保留原文；资料外发仍须经可信策略授权，选择需要脱敏时必须有可验证的处理适配器 |
| 答案生成 | 慧智中枢 DSH 负责最终回答；WeKnora 返回经过授权和版本校验的证据 |
| 管理界面 | 中文，提供处理预览、治理审核、版本发布和运行管理 |
| 部署方向 | Ubuntu 容器化；服务器规格在样本和并发测试后确定 |
| 暂未确定 | 文档总量、总页数、每日增量、模型供应商、费用上限、生产主机及备份恢复目标 |

不预设文档容量，也不按员工人数直接承诺硬件规格。音频、视频、图像向量检索和复杂图谱推理保留后续开发包。

## 2. 当前项目与实施边界

### 2.1 已存在的项目基础

- Node.js / TypeScript DSH 执行层，依赖版本见 [package.json](../package.json)。
- `createCommandDispatcher` 统一业务入口，见 [分流约定](command-routing.md)。
- 任务身份字段 `taskId`、`organizationId`、`requesterId`、可选 `authorizationRef`。
- `knowledge` 插件契约：`describe_capability` 与 `search_knowledge`；搜索输出保留 `hits`、`sourceRef`、`version`。
- 插件连接、契约检查及模拟测试基础，见 [插件契约](plugin-contract-v1.md) 和 [现有验证说明](testing-troubleshooting.md)。

当前仓库已有 P1～P5 插件内核、P6 候选验收内核与数据库迁移，但仍未包含完整的正式知识库服务、主程序管理页面或真实文档验收结果。P0 已将固定 WeKnora 上游源码克隆到被 Git 忽略的 `.runtime/` 用于核验，并新增源码锁定清单和检查命令；这些不等于正式插件已实现。

### 2.2 上游与自建内容

当前 P0 源码基线为 WeKnora `v0.8.2`，commit 与镜像仓库 digest 见 [P0 基线](weknora-p0-baseline.md)。P0 仍须验证依赖、迁移运行和原版流程，并核验 `main` 文档中哪些能力已进入该版本。禁止以浮动 `latest` 作为可复现的正式发布基线。

| 类别 | 实施策略 |
| --- | --- |
| 现有框架 | 复用文档管理、模型适配、异步任务、检索、角色权限及可观测性基础，实际可用范围由 P0 验证 |
| 核心扩展 | 文档版本、发布闸门、权限过滤、原文定位、派生知识失效 |
| 可替换模块 | OCR 适配、清洗、语义切分、实体归一、质量评测 |
| 项目对接 | 建立完整 `knowledge` 插件交付单元：MCP 工具入口、插件治理 API/页面、Worker、WeKnora 引擎和运维配置均由插件负责 |
| 上游维护 | 扩展代码保持明确边界，维护改造清单与迁移记录；上游升级先在隔离环境回归 |

WeKnora 原生界面仅可作为隔离调试入口，正式员工与管理员操作均走 `knowledge` 插件提供的入口。员工正式问答由慧智中枢完成生成。插件内部任何 CLI、REST 或后台任务路径同样执行权限及版本规则；插件是统一交付边界，不要求所有操作都暴露给模型。

## 4. 研发工作包

### P0：基线、样本和接口冻结

预计第 1 周。负责人：后端负责人、测试、业务资料负责人。

当前源码核验与未完成闸门见 [P0 基线与验收记录](weknora-p0-baseline.md)。

- [ ] 核验上游版本、部署组件、模型协议、许可证和必要的兼容修复，记录固定版本。
- [ ] 搭建隔离开发环境；真实业务资料和凭据不进入仓库。
- [ ] 选取约 100～200 份代表文档与 300～500 个问题作为建议样本规模，按实际可用资料调整。
- [ ] 标注答案、来源页码、关键字段、有效期、权限及无答案/冲突案例；分离调参集与验收集。
- [ ] 测量原版解析、检索和回答效果，记录各类型缺陷及 API 成本。
- [ ] 冻结身份映射、证据包、MCP 输出扩展、模型协议及管理 API 的实现契约。
- [ ] 冻结完整 `knowledge` 插件边界、安装/升级/健康检查协议，以及员工 MCP 工具与插件管理 API 的权限分界。
- [ ] 确定首次运行需要的模型供应商、脱敏/外发策略、并发额度、日预算和超时。
- [ ] 将资料量、模型费用和备份目标保留为明确待决项；只在进入相应采购或发布步骤前完成决策。

交付物：基线清单、样本说明、原版测评、接口 Schema、风险清单、后续任务拆分。通过条件：在固定环境复现原版流程，并证明身份传递和来源定位路径可实现。

### P1：权限、版本与任务基础

预计第 2～3 周，依赖 P0。负责人：后端。

实施状态与剩余闸门见 [P1 实施记录](weknora-p1-implementation.md)。按用户要求先完成独立基础代码；下列任务只有接入真实服务并取得集成证据后才可勾选。

- [ ] 建立文档、不可变版本、处理产物、权限、发布记录与任务状态模型。
- [ ] 对接企业身份，校验主程序服务身份及用户授权；建立拒绝优先的权限计算。
- [ ] 为原文、索引、父块、引用和下载建立统一读取闸门。
- [ ] 建立暂存索引与活动发布快照，区分业务有效时间和系统记录时间。
- [ ] 支持幂等请求、过期任务写入隔离、并发发布冲突检测及失败补偿。
- [ ] 建立发布事件可靠投递和基础审计。

交付物：数据库迁移、授权服务、版本服务、任务骨架、契约与并发测试。通过条件：越权读取被拒绝；半成品不可检索；重复任务不重复发布；旧任务不能覆盖新版本。

### P2：解析、清洗、切分与索引

预计第 4～6 周，依赖 P1。负责人：后端/数据处理、前端。

实施状态与真实资料、模型及 WeKnora 集成缺口见 [P2 实施记录](weknora-p2-implementation.md)。按用户要求先完成可独立验证的处理内核；下列任务只有完成对应真实样本与服务验收后才可勾选。

- [ ] 按文件/页面类型选择原生解析或 OCR API，统一输出结构化文本块与位置。
- [ ] 保留表格、条款、阅读顺序、附件和必要的原页图；提供原文对照。
- [ ] 校验漏页、乱码、数字/日期/金额、跨页表格等质量问题，建立待复核队列。
- [ ] 实现完全重复、近重复候选、去噪和过滤；保留原文与清洗变更记录。
- [ ] 实现结构约束下的语义切分、父子片段、长度限制和完整性检查。
- [ ] 将预切分产物接入索引，阻止 WeKnora 再次自动切分。
- [ ] 实现 Embedding 批处理、模型版本、缓存、长度/维度校验、失败重试。
- [ ] 实现关键词与向量索引准备、完整性核对及页/单元格引用。
- [ ] 交付处理中心、解析清洗对照和切分预览。

交付物：可重复运行的入库流水线、标准产物协议、可视化预览、各文档类型质量报告。通过条件：样本内容完整、关键错误可发现且可修复；不通过质量闸门的材料不自动发布。

### P3：问答与慧智中枢接入

预计第 7～8 周，依赖 P2。负责人：后端、DSH 对接、前端。

- [ ] 实现意图、时间、主体、编号识别及有限查询改写。
- [ ] 组合关键词、向量、编号检索；为表格统计接入受控计算和原始行列证据。
- [ ] 在召回、重排前、补充上下文和输出前执行授权/版本校验。
- [ ] 统一重排诊断，支持低相关性、模型不可用等明确结果。
- [ ] 生成含原文、页码、文档版本、有效期和来源类型的证据包。
- [ ] 将完整 `knowledge` 插件的只读 MCP 搜索入口接入既有契约并通过 `plugins check`；治理与反馈接口由同一插件提供。
- [ ] 接入 DSH 的证据 Prompt、引用白名单和严格答案校验；主程序在校验通过后展示正式答案。
- [ ] 实现资料不足、冲突未裁决、需要澄清和降级的中文交互。

交付物：授权用户可使用的部门试用版、MCP 联调记录、检索诊断和问答基线。通过条件：答案引用能打开对应文档版本，禁止以未授权或失效内容构造答案。

### P4：知识治理与发布工作台

| 解析与切分预览 | 原件/解析/清洗/切分联动，页码、表格坐标、父子关系 |
| 清洗审核台 | 去重、噪声、字段疑点、变更差异、接受/驳回及原因 |
| 制度与冲突台 | 有效期、适用范围、权威来源、替代关系、冲突裁决 |
| 版本发布台 | 版本差异、受影响知识、测试结果、发布、定时生效与回退 |
| 检索调试与评测台 | 原问题/改写、各路候选、过滤原因、重排和失败样本 |
| 运行管理台 | 权限、审计、队列、模型调用、费用、告警和恢复情况 |

页面中的管理员诊断信息按权限显示，普通员工只看到回答所需的来源、有效性和限制。

## 7. 测试与验收

### 7.1 原则

- 数据处理、接口、权限和发布逻辑优先 TDD：先写关键行为和失败用例，再实现。
- 单元测试不代替真实文件解析；模型 API 连通不代替问答质量；模拟插件不代替正式授权。
- 评测区分文档类型和问题类型，保留失败样本；不得只报告总体平均值。
- 测试集中的无答案、历史版本、冲突、越权和恶意文档指令必须单独统计。
- 接口、配置或模型变更触发相应回归；未修改的低风险文档只做文档检查。

### 7.2 发布硬条件

| 编号 | 必须通过的行为 |
| --- | --- |
| G-01 | 未授权用户无法通过搜索、父块、预览、下载、缓存、图谱、Wiki、会话或 MCP 读取内容 |
| G-02 | 发布完成后的当前查询不采用旧版本；模拟旧索引仍存在时依然成立 |
| G-03 | 未来生效、过期、撤销和未发布内容不进入当前有效答案 |
| G-04 | 新版本处理失败不误替换有效版本；紧急撤销立即停止旧版服务 |
| G-05 | 重复任务、并发更新、断点重试和旧回调不产生重复发布或覆盖 |
| G-06 | 关键条款、条件、否定词、表头和单位不被无记录删除；引用可定位到原版本 |
| G-07 | 资料不足、冲突未裁决或关键校验失败不会输出确定性业务结论 |
| G-08 | 权限撤销后缓存及重新打开的历史内容执行最新权限；严格模式展示前再校验 |
| G-09 | 原件和元数据备份可恢复，索引可重建，抽样来源和回答可复核 |

以上是测试验收要求，不代表可以对现实中所有未知输入承诺绝对无错误。

### 7.3 建议量化目标

以下目标在 P0 根据已标注样本、模型和测试负载冻结；未冻结前为建议值。

| 指标 | 建议目标 | 统计口径 |
| --- | --- | --- |
| 关键字段解析准确率 | ≥99% | 约定清晰度样本中的金额、日期、编号和单位，人工标注对比 |
| 必要证据覆盖率 Recall@20 | ≥95% | 有答案问题前 20 条候选是否包含全部必要证据，跨文档题单列 |
| 答案正确率 | ≥90% | 业务评审标准；单列事实正确、条件完整和引用支持 |
| 无答案/冲突正确处理率 | ≥95% | 冻结的无证据和无法裁决题集，区分澄清与拒答 |
| 普通问答 P95 完成时间 | 初始目标 ≤20 秒 | 10 个持续并发、固定资料/模型/输出长度，含 DSH 与 API 总链路 |
| 入库吞吐与费用 | P0 测量后设定 | 每千页、每类文档、失败复核率、每日更新量分别报告 |

性能测试先做稳定负载，再做入库与提问混合负载。记录错误率、排队时间、模型限流、每阶段延迟与成本；不因缓存命中掩盖真实未命中性能。

### 7.4 代表性业务案例

1. 报销上限由 500 元改为 800 元，指定下月生效；本月与下月回答采用不同版本。
2. 总部规则和分公司例外并存，问题未指定所属部门时需要澄清。
3. 扫描合同金额中的小数点识别不清，系统定位原页并进入复核。
4. PDF 跨页表格丢失重复表头，处理后能正确关联列名与单位。
5. 同文档在两个权限不同的部门出现，去重不能扩大可见范围。
6. 发布新版本时索引清理失败，旧片段仍不能参与当前答案。
7. 用户权限在生成过程中撤销，严格模式不展示未授权结果。
8. “全部合同金额合计”使用受控表格计算并引用原始行列，不能用相似片段估算。

## 8. 发布、迁移与回退

- 新表/字段先采用兼容迁移，在隔离环境使用样本验证，再执行生产迁移。
- 存量文档登记来源和版本；缺少有效期或权限的材料进入待确认，不能默认全部公开或有效。
- 新索引影子构建、对比评测后切换；记录应用版本、数据库迁移、索引配置及模型配置。
- 应用回退、索引回退和业务文档回退分别定义；不能只切容器就认为数据已回退。
- 发布前完成备份、恢复演练、健康检查和回退路径验证。
- 生产发布、付费批量处理和实际资料外发按当时授权范围执行。

## 9. 风险与处理

| 风险 | 处理 |
| --- | --- |
| OCR 结构信息不足 | P0 用真实表格和扫描件验证接口；补充结构化适配，必要时备用解析器 |
| 语义切分成本高或效果倒退 | 与结构切分对照评测，复用缓存，LLM 只处理模糊边界 |
| 源资料无有效期或权威归属 | 指派资料负责人，补充元数据后再参与制度回答 |
| 上游升级覆盖改造 | 固定版本、独立扩展、补丁清单和契约/行为回归 |
| 身份映射或访问入口遗漏 | 统一授权服务，按所有读取面建立越权测试矩阵 |
| API 限流拖慢员工提问 | 入库与在线独立并发和额度，受控重试、排队和明确超时 |
| 自动摘要/图谱遗留旧事实 | 来源依赖、活动版本校验、失效隔离及增量重建 |
| 模型供应商暗中更新模型 | 保存返回的模型标识与配置指纹；定期基准回归，不能假设输出完全可复现 |
